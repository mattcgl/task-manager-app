# Project working instructions

Before every project action, read `DEVELOPMENT_PLAN.md` and confirm that the action supports the current milestone and respects the agreed scope, cost, and architecture. This includes edits, commands, dependency changes, tests, and release operations. If the plan is missing or contradictory, resolve the planning issue before implementation.

- The plan is the project's source of truth. Follow newer user instructions and update the plan to reflect agreed changes before dependent work.
- Keep milestone status, decisions, verification results, and material limitations current. Do not silently expand scope.
- Development is authorized. Work through the current milestone in the plan and commit verified milestone implementation checkpoints; distinguish implementation completion from pending physical-device acceptance.
- Prioritize iPhone, free development, offline local storage, and readable code for a beginner learning React/TypeScript.
- No paid services or purchases without explicit user authorization. Defer backend, automation, reminders, and other excluded features.
- Use small, reviewable changes and explain new concepts in context. Run checks proportionate to each change.
- Do not claim iPhone/Android device testing without evidence. Record checks that require the user's physical device.
- Never commit personal app data, exported backups, credentials, or signing material. Use synthetic data for portfolio artifacts.
- Keep this file concise; detailed requirements belong in `DEVELOPMENT_PLAN.md`.
